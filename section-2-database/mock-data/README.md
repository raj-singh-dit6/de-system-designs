# Mock sales data

These CSV files are intentionally small, deterministic fixtures for local
development and demonstrating the analyst queries. Docker loads them through
`sql/04_load_mock_sales_data.sql` when PostgreSQL creates a fresh volume.

## `dim_product.csv`

This file maps directly to the insertable business columns of
`analytics.dim_product`. `product_key` and `created_at` are generated by
PostgreSQL.

## `fact_sales_order_line.csv`

This is a **load-ready source file**, rather than a direct `COPY` file for the
fact table. It uses readable business identifiers in place of surrogate keys:

| CSV field | Resolved target |
| --- | --- |
| `membership_id` | `analytics.dim_member.member_key` |
| `item_name` + `manufacturer_name` | `analytics.dim_product.product_key` |
| `order_status` | `analytics.dim_order_status.order_status_key` |

The remaining columns map directly to `analytics.fact_sales_order_line`. The
sale-time `unit_price` and `unit_weight_kg` are deliberately provided in the
fact data; they must not be recalculated from the current product catalogue.

The fixture includes completed, processing, and cancelled orders. Therefore,
the two completed-order analyst queries can demonstrate their status filter.
